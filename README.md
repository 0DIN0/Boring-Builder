# Boring Builder

A self-hosted web app that turns a plain-English description into a working
software project, using your **local** Ollama models. It plans the files, writes
each one, checks that the Python compiles, and hands you a downloadable zip.

Runs entirely on your own machine. No cloud, no API keys, no data leaving your box.

- **Describe a subsystem, get a project.** One focused spec at a time builds far
  better than "make me a whole app".
- **Make your own models in a click.** A simple form creates specialised builder
  models (a website builder, an API builder, and so on) and saves the Modelfile.
- **Knows your hardware.** Detects your CPU, RAM and GPU and recommends models
  that will actually fit — no more out-of-memory surprises.
- **Built-in guidance.** "How to use" pages and an "i" icon on every field.
- **Dark, calm interface.** Navy-and-grey, keyboard friendly, responsive.

> Honest expectations: a small model on a modest GPU writes solid single files
> and well-scoped subsystems. It won't one-shot a production app to the standard
> of a frontier hosted model. Keep scopes small and treat the output as a fast
> first draft. Every model call goes through one place in the code
> (`ModelClient.chat`), so you can point it at a hosted API later if you want
> frontier-quality output without changing anything else.

## Requirements

- Python 3.10+
- [Ollama](https://ollama.com) running locally, with at least one model pulled
  (e.g. `ollama pull qwen2.5-coder:3b`)
- Linux for the one-command installer; any OS for manual/dev running

## Quick start (Linux, systemd)

```bash
sudo ./install.sh
```

It builds a virtualenv, asks you to set an admin username and password,
generates a secret key, installs a `boring-builder` systemd service, and starts
it. Then open **http://localhost:5001**.

Runs on port **5001** by default, so it can sit alongside the companion chat app
(which uses 5000) on the same machine.

Useful commands:

```bash
journalctl -u boring-builder -f      # live logs
sudo systemctl restart boring-builder
sudo ./uninstall.sh                  # remove the service (keeps your data)
```

## Quick start (any OS, no systemd)

```bash
./start.sh
```

Or manually:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env      # then edit it
.venv/bin/python run.py
```

## First run

1. Sign in with the admin account you set during install.
2. Go to **Settings → Hardware** to see what your machine can run.
3. Under **Builder models**, create a model (start from an example in
   `modelfiles/`).
4. On the **Build** page, describe one subsystem and click **Build**.
5. Download the zip, read its README, and run it.

## Making models

A "builder model" is just a base model plus a set of instructions (a Modelfile).
Two examples ship in `modelfiles/`:

- `builder.example.Modelfile` — a general project builder
- `website.example.Modelfile` — static HTML/CSS/JS websites only

Create one from the UI (**Builder models → New builder model**), or from the
command line:

```bash
ollama create builder-web -f modelfiles/website.example.Modelfile
```

Models you make in the UI are also saved to `modelfiles/builder/` so you can
version and tweak them.

## Configuration

All settings have sensible defaults and most are editable in the UI. Environment
variables (see `.env.example`) override them:

| Variable | Purpose | Default |
|---|---|---|
| `SECRET_KEY` | Flask session key | generated by installer |
| `DATA_DIR` | Where the database and files live | `instance/` |
| `OLLAMA_HOST` | Ollama daemon URL | `http://localhost:11434` |
| `PORT` | Web server port | `5001` |
| `BUILDER_MODEL` | Default builder model | blank (choose in UI) |
| `BUILDER_OUTPUT_DIR` | Where builds are saved | a folder in `DATA_DIR` |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | Bootstrap admin (first run only) | `admin` / `admin` |
